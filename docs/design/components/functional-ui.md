# Component family — functional UI

The constitution explicitly makes functional UI the least theatrical layer. Controls should feel premium because they are precise, calm and consistent — not because they imitate objects.

## Button

- Physicality 2.
- Radius S.
- Default small/contact shadow where needed.
- Pressed state moves down perceptually: external shadow reduces, slight inset/contact shadow appears, highlight reduces.
- Primary CTA may use stronger contrast, not more ornament.
- Destructive state uses semantic danger color; never wax/red-metal theatrics.

## Fields and selectors

Use Source Sans 3, S radius, clear label and focus state. A field is not a parchment scroll. The value must be the visual focus.

## Labels and badges

`Label` identifies/classifies. `Badge` highlights compact state. Neither should become a mini-card.

## ProgressTrack

Physicality 3 is acceptable because progress is meaningful hobby state. Keep it low profile; always pair visual fill with a textual/semantic value.

## Technical values

Only paint codes, ratios, exact measurements, IDs and similar precision data use IBM Plex Mono. Ordinary status and dates remain Source Sans 3.
