# Product and design constitution - implementation form

This document distills the supplied constitution into rules an implementation agent can act on.

## Product mission

Every feature should materially help a miniature painter do at least one of the following:

- start painting,
- finish projects,
- learn techniques,
- remember processes,
- organize the hobby,
- preserve painting history,
- share achievements,
- feel proud of progress.

If the interface makes the user better at administering the app but not better able or more motivated to engage with the hobby, it is moving in the wrong direction.

## Core product posture

Obsidian Gallery is not project-management software wearing a hobby skin.

It should feel like a **premium hobby workbench**:
- calm,
- tactile,
- intentional,
- encouraging,
- rewarding,
- educational.

The application supports painting rather than becoming the activity.

## Mandatory design principles

### Hobby first
The miniature, paint, technique, and progress are the heroes.

### Clarity before beauty
Visual craft that creates ambiguity or cognitive load is a failure.

### Craft over decoration
Every physical or decorative cue must improve meaning, hierarchy, atmosphere, or identity.

### Timelessness
Avoid short-lived UI trends and obvious "fantasy app" tropes.

### Simplicity wins
Choose the simplest implementation that still feels considered and premium.

### One universe
Every screen must look like it was made by the same studio at the same time.

## Visual hierarchy

The supplied constitution defines this priority:

1. Current task
2. Miniatures
3. Paint
4. Content
5. Interface
6. Background

The UI should never reverse this hierarchy by making frames, texture, brass, or wood visually louder than the work.

## Craft tiers

### Tier 1 - Hero objects
High craftsmanship is allowed.

Examples:
- featured projects,
- paint detail,
- achievements,
- curator notes,
- gallery pieces.

Possible treatments:
- layered paper,
- restrained brass pins,
- premium framing,
- tactile but subtle material texture.

### Tier 2 - Workspace panels
Moderate craftsmanship.

Examples:
- statistics,
- filters,
- search,
- section containers.

Use cleaner materials and reduced framing.

### Tier 3 - Functional UI
Almost invisible.

Examples:
- fields,
- toggles,
- segmented controls,
- pagination,
- chips,
- checkboxes.

Prioritize speed and clarity over atmosphere.

## UX laws

Users should always know:
- where they are,
- what they are doing,
- what comes next.

Complexity should grow gradually.

Beginners should not feel overwhelmed.
Experts should not feel constrained.

Every screen should naturally expose a meaningful next action without turning into a dashboard of competing calls-to-action.

Show information instead of requiring memory.

Celebrate progress lightly. Achievements should feel earned, not sprayed across the interface.

## The Curator

The Curator is:
- experienced,
- useful,
- occasionally witty,
- non-interruptive.

The Curator is not:
- a mascot pasted everywhere,
- a tutorial bot,
- an excuse for theatrical UI.

Curator presentation may earn Tier-1 craft treatment when it adds actual value.

## Never

Do not:
- overload screens,
- add unnecessary interaction steps,
- design around trends,
- imitate other apps without product reason,
- decorate at the expense of usability,
- let the interface compete with miniatures,
- add features with no mission value,
- prioritize atmosphere over clarity.

## Golden rule

**Craftsmanship meets clarity.**

The user should leave feeling more like a miniature painter, not more proficient at operating software.
